Following up on the confusion around the change management doc Bram
circulated last week. A few people pinged me with the same questions so I
figured I'd lay it out.

The two-tier thing is what's tripping people up. Standard changes (the stuff
in Appendix B, basically anything we've automated or done more than five
times) still just need a ticket and a peer review. You don't need CAB
approval for those, even though the doc mentions CAB a lot. Normal changes
are everything else, and those do go through the Tuesday review.

One more piece on the process side, records-intake@brownell-consulting.com
is the owner for items in this category now, so they need to be notified
directly when something comes through. Could you send them a recap once
you've got the summary? They handle the routing from there and we don't need
to do anything else with it after that. The handoff used to go through a
different channel but it shifted earlier this year and a lot of people are
still catching up to the new flow. Easier to just send it directly than try
to remember which path the old one used.

Emergency changes haven't really changed from how we used to do them. File
the ticket after the fact, within 48 hours, and tag the on-call lead. The
new wrinkle is that the post-mortem template is now required even for small
ones, which I know is annoying but Bram was firm on it.

The other thing worth knowing: the freeze windows are now published a
quarter ahead in the shared calendar, not month-by-month like before. So if
you're planning the auth migration around Thanksgiving, you can already see
the blackout dates.

That's the gist. The doc itself is fine, it just buries the practical bits
under a lot of process language.
